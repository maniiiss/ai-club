# 模型计费倍率技术设计 v1

## 目标

桌面端模型下拉列表只展示 `free` 或模型倍率（例如 `0.1x`、`1x`、`2x`）。当前已选择模型按钮、桌面端其他区域不展示计费信息。实际扣费仍使用模型的输入/输出 Token 单价。

## 定价模型

平台在 `credit_global_config` 中维护统一的 1x 基准输入/输出单价；模型在 `ai_model_config` 中维护 `billing_multiplier`。保存模型倍率时由后端换算并写入既有实际单价字段：

```text
模型输入单价 = 1x 基准输入单价 × 模型倍率
模型输出单价 = 1x 基准输出单价 × 模型倍率
```

缓存命中输入单价继续使用模型已有的可选配置；未单独配置时按实际输入单价的 50% 计算。Token 扣费链路不读取倍率直接扣费，因此基准价变化后由服务同步重算已有倍率模型的实际输入/输出单价。

## 管理入口与接口

管理端模型管理页的“计费基准”入口维护：

- `1x 基准输入单价（积分/千 token）`
- `1x 基准输出单价（积分/千 token）`

接口使用模型管理权限：

- `GET /api/model-configs/pricing-base`：`model:view`
- `PUT /api/model-configs/pricing-base`：`model:manage`

模型新增/编辑请求增加 `billingMultiplier`。为了兼容旧管理端仍保留实际单价字段；旧请求提交实际单价时，后端按当前 1x 输入基准反推展示倍率。

## 桌面端链路

后端 CLI 模型摘要下发 `billingMultiplier`，CLI 将其作为模型元数据保留到 RPC 模型对象，桌面端 `ModelPicker` 只在下拉列表项标题中渲染标签：倍率缺失或不生效时渲染 `free`，否则渲染格式化后的 `${倍率}x`。PI 的 `cost` 继续为 0，避免展示倍率改变底层模型成本字段或实际扣费。

## 数据迁移

`V153__model_pricing_multiplier.sql` 为全局配置增加默认 1x 输入/输出单价，为模型增加可空倍率字段，并为已有按 Token 计费模型回填倍率。倍率为空的模型不会改变现有实际单价；未启用 Token 计费的模型始终按 `free` 展示。
