# 改造方案：gitpilot 复用 Pi 原生 /login 对接平台 + /model 只留平台模型

## 背景与目标

当前 gitpilot extension 自建了一套 `/gitpilot login` 命令做设备授权，gitpilot provider 没声明 `oauth`，所以不出现在 Pi 原生 `/login` 列表里；`/model` 也因为没接好登录、加上 pi 内置 38 个 provider 的存在，选到的是 pi 自己的模型。

目标：
1. **复用 Pi 原生 `/login`**——把设备授权流程包进 `provider.oauth.login`，平台作为一个登录项出现在 `/login`
2. **删除 `/gitpilot` 命令**（login/logout/status 全删），登录登出统一走原生 `/login` `/logout`
3. **`/model` 只显示平台模型**——移除 pi 内置 provider catalog
4. 登录后平台模型可被选中

关键技术依据（已调研确认）：
- `ProviderConfig.oauth`（`src/core/extensions/types.ts:1437`）是 `/login` 扩展点；`oauth.login(callbacks)` 的 `callbacks.onDeviceCode({userCode, verificationUri, intervalSeconds, expiresInSeconds})` 正好展示设备码
- `OAuthCredentials = { refresh, access, expires, [key]: unknown }`（`pi-ai/dist/auth/types.d.ts:21`），gpt_ token 放 `access`
- `pi.unregisterProvider()` 对内置 provider **无效**（只删 extension provider，builtins 会重建），无配置项可关 catalog——移除内置 provider 只能改 `src/core/model-runtime.ts` 的 `create()`

## 改动清单（按文件）

### 1. `src/extensions/gitpilot/platform-model.ts`（核心：加 oauth）
给 gitpilot provider 的 `registerProvider` 配置加 `oauth` 字段，把设备授权流程包进 `oauth.login`：
- `login(callbacks: OAuthLoginCallbacks)`：
  - 复用 `createDeviceAuthorization` / `pollDeviceToken`（来自 `api.ts`）
  - `getPlatformUrl()` 为空时，用 `callbacks.onPrompt` 让用户输入平台地址（替代原 `ctx.ui.input`）
  - `callbacks.onDeviceCode({...})` 推设备码给 TUI 展示
  - `openBrowser(verificationUri)` 自动开浏览器（保留现有 `utils/open-browser.ts`）
  - 按 `intervalSeconds` 轮询 `pollDeviceToken`，`signal` 中止时退出
  - 拿到 token 后 `saveCliToken(platformUrl, accessToken)` 存 keyring + `loadCliToken` 装入 `GITPILOT_CLI_TOKEN` 进程缓存（保持现有 refreshModels/streamSimple 取 token 路径不变）
  - 返回 `{ access: accessToken, refresh: accessToken, expires: 远期 }`
- `refreshToken(credentials)`：no-op 返回原 credentials（gpt_ 是长期令牌）
- `getApiKey(credentials)`：返回 `credentials.access`——让 pi 判定 gitpilot provider"已配置鉴权"，从而进 `configuredProviders`、出现在 `/model`
- `streamSimple` / `refreshModels` / `toModelConfig` 保持不变（仍通过 keyring 的 gpt_ token 换 gms_ 会话再走平台代理）

### 2. `src/extensions/gitpilot/platform-auth.ts`（删除命令，保留设备授权工具）
- 删除 `platformAuthExtension`（`/gitpilot` 命令注册）及其 `login/logout/status` 命令实现
- 设备授权的核心逻辑（`createDeviceAuthorization`+`pollDeviceToken`+`openBrowser`+轮询）已搬到 `platform-model.ts` 的 `oauth.login`，本文件可整体删除或仅保留 `normalizePlatformUrl` 导出（看 index.ts 是否还引用）

### 3. `src/extensions/gitpilot/index.ts`（清理入口）
- 移除 `platformAuthExtension(pi)` 调用
- 保留 `platformModelExtension(pi)`（现含 oauth）和启动时 `loadCliToken` 预热

### 4. `src/core/model-runtime.ts`（移除内置 provider catalog）⚠️ 改 pi 核心源码
- `create()` 第 143-155 行：把 `builtinProviderCatalog.builtinProviders().map(...)` 替换为空数组 `[]`
- 加中文注释说明：GitPilot 二开定制——不加载 pi 内置 provider catalog，只保留 extension 注册的平台 provider；`radius` 动态 provider 不受影响（它走 `configureRadiusProviders` 从 config 独立实例化）
- 效果：`defaultBuiltins`/`builtins` 为空，`providerIds()` 不含内置 id，`recomposeProvider` 对内置 id 走删除分支，`/model` 只剩 gitpilot 平台模型
- 这是"只留平台模型"的唯一可靠方式（extension API 与配置均无法做到）

### 5. 登录后自动选中平台模型（增强）
- 在 gitpilot extension 监听 `session_start`：若当前无 model 且平台模型已就绪，自动 `pi.setModel(第一个平台模型)`
- 需等 `refreshModels` 完成；若实现复杂则降级为提示用户 `/model` 选择

### 6. 文档更新
- `gitpilot-cli/README.md`：使用说明 `/gitpilot login` → `/login`，`/model` 说明改为平台模型
- 按 AGENTS.md 要求，本次涉及登录流程与 provider 体系变化，补充 `docs/design-docs/` 或更新相关说明

## 已知限制
- **`/logout` 清理不完整**：pi 原生 `/logout` 只删 credential store（OAuthCredentials），keyring 里的 gpt_ token 不会自动 revoke/清除（ExtensionAPI 无 logout 事件钩子）。下次 `/login` 会覆盖 keyring；如需立即失效需平台侧 revoke。实现时尽量在 `session_shutdown` 或可挂钩处补清，无法挂钩则文档标注。
- **改 pi 核心源码**：`model-runtime.ts` 的改动在后续 pi 升级 merge 时需手动维护（gitpilot 本就是 fork，可接受）。

## 验证方式
1. `cd gitpilot-cli && npm run build`（tsc 通过）
2. 启动平台服务栈后跑 `gitpilot`：
   - `/login` 列表出现 "GitPilot 平台" 登录项
   - 选中后走设备授权，TUI 显示设备码，浏览器打开授权页
   - 授权完成，token 存入 keyring
3. `/model` 只显示平台模型（无 anthropic/openai 等）
4. 选模型后推理实际走平台（pi-runtime 9011 / backend 8080 日志可见请求）
5. `/logout` 清除登录态
