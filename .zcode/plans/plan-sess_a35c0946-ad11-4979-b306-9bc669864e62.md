# 修复 deepseek-v4-flash 思考级别切换无效

## 根因（真正）
`gitpilot-cli/src/extensions/gitpilot/platform-model.ts:73` 的 `toModelConfig` 对**所有**平台模型硬编码 `reasoning: false`。pi-ai 中 `getSupportedThinkingLevels` 对 `!model.reasoning` 直接返回 `["off"]`，导致 sidecar `setThinkingLevel` 把用户选的 low/medium/high 全部 clamp 回 `off`，桌面端回读后永远显示 `off`。

pi-ai 实际上把"启用思考"和"用 developer role"解耦了：`developer` role 只在 `model.reasoning && compat.supportsDeveloperRole` 同时为真时才用。而 pi-ai 内置 deepseek-v4-flash 的 `compat` 本身就是 `supportsDeveloperRole:false`（原生 deepseek 也用 system role）。所以原作者设 `reasoning:false` 是基于误解；正确做法是复刻 pi-ai 的 deepseek 配置。

reasoning 流转链已验证成立：`setThinkingLevel → agent.state.thinkingLevel → config.reasoning（agent.js:286）→ options.reasoning（agent-loop.js:194）→ 经 sdk.ts/model-runtime.ts/provider-composer.ts/platform-model.ts 透传 → openAICompletionsApi().streamSimple（openai-completions.js:408 读 options.reasoning）`。但触发 deepseek 的 `thinking:{type:"enabled"}` 分支需显式 `compat.thinkingFormat:"deepseek"`（gitpilot provider/proxyBaseUrl 不会被自动检测为 deepseek）。

## 本次会话已完成的桌面端改动（保留，互补）

## 风险与说明
- 平台代理需透传 `thinking`/`reasoning_effort` 参数并回传 `reasoning_content`；无法离线验证，需运行时确认。若平台代理剥离了这些参数，思考不会生效，届时需在平台代理侧处理。
- deepseek-v4-flash 按 pi-ai 参考仅支持 off/high/max，桌面端暴露 off/high（max 不在桌面 4 档）。若实际支持 low/medium，可放宽 `thinkingLevelMap`。
- 后续可演进为后端配置化（`AiModelConfigEntity` 增 reasoning 字段 + `/api/cli/models` + 管理端 UI），让任意模型可配而无需改 sidecar 代码；本次不做。
