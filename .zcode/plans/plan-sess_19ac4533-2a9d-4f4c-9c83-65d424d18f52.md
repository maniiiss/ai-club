# Plan: 本地 fork plan-mode 扩展，支持"其他"自定义反馈（不打断 plan 模式）

## 背景与根因
- plan 确认走 `@narumitw/pi-plan-mode` 的 `showReadyPlanMenu`/`showPlanModeMenu`，它们用 pi-tui-kit 的 `runMenu`→`runDialogMenu`→`ctx.ui.select`。
- `runDialogMenu`（`pi-tui-kit/dist/runtime.js:299-301`）用 `rows.find(row => row.label === choice)` 精确匹配，**自定义 choice 会被丢弃并 `continue` 重弹**（死循环）。
- 因此必须让 plan-mode **绕过 runMenu、直接调 `ctx.ui.select`**，自己识别非预设 choice 作为用户反馈。
- `ctx.ui.select(title, options, {signal, timeout})` 返回 `string | undefined`（`rpc-mode.ts:201-205`）；desktop `respondValue(自定义文本)` 全链路回传为该 string。
- 闭环成立：自定义 choice → `sendPlanModeUserMessage("反馈+原计划")` → 新回合（`before_agent_start` 清 state，但消息含原计划）→ AI 改计划 → `agent_end`→`plan_mode_complete`→`acceptCompletedPlan`→`onAgentSettled`→`showPlanReadyMenu` 再弹。plan 模式 `enabled` 全程保留，不打断。

## 改动清单

### 1. 本地 fork @narumitw/pi-plan-mode 源码
- 将 `gitpilot-cli/node_modules/@narumitw/pi-plan-mode/src/` 下全部 **18 个 .ts 文件**原样拷贝到 `gitpilot-cli/src/extensions/plan-mode/`。
- 文件间相对 import（`./xxx.js`）保持不变；外部包 import（`@narumitw/pi-tui-kit`、`@earendil-works/*`）走 loader 的 VIRTUAL_MODULES/alias，无需改动。
- 在 fork 目录顶部加 `README.md` 或注释说明：fork 自 @narumitw/pi-plan-mode@0.44.0，本地化为支持自定义反馈；上游升级时需手动合并。

### 2. 改 `gitpilot-cli/src/core/extensions/loader.ts`（4 处绑定点指向本地 fork）
- **line 30**：`import * as _bundledPlanMode from "@narumitw/pi-plan-mode/src/index.ts"` → `from "../../extensions/plan-mode/index.ts"`
- **line 77**：VIRTUAL_MODULES 条目 `"@narumitw/pi-plan-mode/src/index.ts": _bundledPlanMode` 保持（value 已是本地 fork，key 不变以便 curated entry 仍能匹配）
- **line 99**：`const planModeEntry = require.resolve("@narumitw/pi-plan-mode/src/index.ts")` → `const planModeEntry = path.resolve(__dirname, "../../extensions/plan-mode/index.ts")`
- **line 146**：alias 条目 `"@narumitw/pi-plan-mode/src/index.ts": planModeEntry` 保持（planModeEntry 已指向本地）
- curated-extension-manifest.ts 的 `entry`/`version`/`packageName` **不动**（保留重复安装保护比对能力）。

### 3. 改 fork 内 `plan-action-menus.ts`：绕过 runMenu，直接 ctx.ui.select
- **`showReadyPlanMenu`**：删除 `defineMenu/runMenu`，改为：
  ```ts
  const labels = ["Implement this plan", "Save for later", "Stay in Plan mode", "Exit Plan mode"];
  const choice = await ctx.ui.select("Proposed plan ready. What next?", labels, { signal: options.signal });
  if (!options.isCurrent()) return;
  if (choice === "Implement this plan") { await options.implement(); return; }
  if (choice === "Save for later") { options.save(); return; }
  if (choice === "Stay in Plan mode") { options.stay(); return; }
  if (choice === "Exit Plan mode") { options.exit(); return; }
  if (choice) options.refine(choice);   // 自定义反馈
  // choice === undefined（取消）→ 当 stay，不操作
  ```
- **`showPlanModeMenu`**：改为 `while` 循环 + `ctx.ui.select`（保留原 runMenu 的 stay/close 语义）：
  - `Show latest proposed plan` → `options.show(); continue`（原 action 返回 close，但 show 后用户通常还想看菜单；按原 runMenu 的 close 语义改为 `return`，与原行为一致——见下方验证项）
  - `Configure Plan-mode tools` → `await options.tools(); continue`（原 action 返回 stay，留菜单）
  - `Implement/Save/Finalize/Stay/Exit` → 对应 `return`
  - `choice === undefined` → `return`
  - 自定义 choice 且 `hasReadyPlan` → `options.refine(choice); return`；无 ready plan → `continue`（忽略，留菜单）
- `ReadyPlanMenuOptions` 与 `PlanMenuOptions` 接口新增 `refine(feedback: string): void`（`PlanMenuOptions` 的 refine 仅 `hasReadyPlan` 时调用）。
- 其他菜单（`showActiveImplementationMenu`、`showSavedPlanMenu`、`showToolSelector`）**保留 runMenu 不动**，它们不涉及"确认"语义。

### 4. 改 fork 内 `plan-mode.ts`：接入 refine 回调
- `showPlanReadyMenu`（~line 718）调用处加 `refine`：
  ```ts
  refine: (feedback) => {
      const plan = state.latestPlan?.trim();
      sendPlanModeUserMessage(
          `用户对当前计划的反馈：${feedback}\n\n当前计划：\n${plan ?? "（无）"}\n\n请根据反馈修改计划，完成后再次调用 plan_mode_complete 提交新计划。`,
          ctx,
      );
  },
  ```
- `showPlanMenu`（~line 695）调用处同样加 `refine`（仅 `hasReadyPlan` 分支会用到）。
- 复用现有 `sendPlanModeUserMessage`（line 473）与 `state.latestPlan`，不新增发送通道。

### 5. desktop 端（已实现，无需再改）
- `ExtensionUISelectCard` 的"其他"输入框（`ExtensionUIModal.tsx`）回车 `respondOnce({ value: text })` → sidecar `select` 返回该文本 → fork 识别为 refine。
- `isActionSelect` 判定（title !== "选择要设计开发的需求"）对 `"Proposed plan ready. What next?"` 和 `"Plan mode"` 都成立 → 浮层 + "其他"输入框。
- 可选小改：把"其他"输入框 placeholder 从"其他…（回车提交）"改为"输入对计划的反馈…（回车提交）"，语义更清晰。

## 风险与备注
- **fork 维护**：上游 @narumitw/pi-plan-mode 升级时需手动合并到本地 fork。fork 顶部注释标注版本来源。
- **runMenu 行为差异**：`showPlanModeMenu` 改 `ctx.ui.select` + `while` 后，`Show latest proposed plan` 的 close 语义需与原 runMenu 对齐（原 action 返回 `{kind:"close"}`）。实现时按原 action 的 transition 决定 `return`/`continue`。
- **custom choice 恰好等于预设 label**：极低概率，plan-mode 按 label 精确匹配会当预设处理，可接受。
- **不改 pi-tui-kit**：所有改动在 plan-mode fork 内，pi-tui-kit 的 runDialogMenu 不动（其他菜单仍用）。
- **AGENTS.md**：本改动涉及跨模块边界（新增本地 fork 扩展 + loader 绑定变更），需在 `docs/architecture.md` 或 `docs/design-docs/` 补一段说明 plan-mode 本地 fork 的原因与加载方式。
