# GitPilot Pi 生产力扩展：新增 pi-rtk-optimizer 内置精选扩展 开发方案

## 一、调研结论

`pi-rtk-optimizer`（MIT，作者 MasuRii，仓库 github.com/MasuRii/pi-rtk-optimizer）是一个 Pi 扩展，做两件事：

1. **命令重写**：把 `bash` 工具命令自动重写为 `rtk` 等效命令（`mode=rewrite`），或仅通知建议（`mode=suggest`）。依赖外部 `rtk` 二进制。
2. **输出压缩**：对 `bash`/`read`/`grep` 工具输出做多阶段压缩（ANSI 剥离→测试聚合→构建过滤→Git 压缩→Linter 聚合→搜索分组→源码过滤→智能截断→硬截断），减少上下文占用。**不依赖 rtk 二进制**。

- 最新版本 `0.9.0`；peerDependencies 声明 `@earendil-works/pi-coding-agent ^0.80.0`（GitPilot 宿主是 0.81.1 fork）。
- 入口 `./index.ts`，`pi.extensions: ["./index.ts"]`。
- 斜杠命令：`/rtk`（TUI 设置模态框）、`/rtk show|path|verify|stats|clear-stats|reset|help`（文本输出）。
- 事件钩子：`tool_call`（重写）、`tool_result`（压缩）、`tool_execution_*`（流式清理）、`before_agent_start`、`session_start`/`agent_end`。
- 配置开关：顶层 `enabled`（主开关）、`mode`、`guardWhenRtkMissing`、`showRewriteNotifications`；`outputCompaction.enabled` 及一系列子开关。**用户想要的"rtk 开关"上游已支持**。
- 配置默认写 `~/.pi/agent/extensions/pi-rtk-optimizer/config.json`，但支持 `PI_CODING_AGENT_DIR` 重定向。
- 0.9.0 带 postinstall 检查 `/.pi/agent/extensions/` 路径并运行 `patch-vulnerable-deps.mjs`；overrides 含 `protobufjs:7.6.3`、`ws:8.21.0`（与 GitPilot 现有 overrides 体系一致）。

## 二、范围界定

v1 设计的四个扩展（slopchop/goal/plan/subagents）及其 Desktop 适配（Git Review Workbench、subagent Windows 子进程验证）**本次不实施**，仅在 curated manifest 中预留结构。本次聚焦：

1. 落地 v1 的 **curated extension 基础框架**（manifest 类型、分级加载、bundledExtensions、重复安装保护、配置目录桥接）。
2. 把 **pi-rtk-optimizer 作为首个 curated 扩展完整接入**（CLI 原生 + Desktop 标准 RPC + rtk 开关 GUI）。
3. 在 v1 设计文档基础上**新增 pi-rtk-optimizer 设计章节**。

理由：rtk-optimizer 的能力（输出压缩/命令重写）是后台事件钩子型，不依赖 Review Workbench 或子进程 transport，可独立闭环；v1 四扩展各有重型 Desktop 适配依赖，宜作为后续 P1+ 阶段。

## 三、核心设计决策

### D1. 内置精选扩展，版本精确锁定
- `gitpilot-cli/package.json` 增加依赖 `"pi-rtk-optimizer": "0.9.0"`（精确版本，不用 `^`）。
- Bun sidecar 构建期把 factory 与依赖打入可执行文件；MSI/NSIS 不在用户机跑 `npm install`。
- 用户执行 `pi install npm:pi-rtk-optimizer` 时，包管理器比对 curated manifest 命中 `pi-rtk-optimizer`，提示"已由当前 GitPilot 版本内置"，拒绝重复安装（v1 §5.2）。

### D2. peer 兼容性不阻断
- pi-rtk-optimizer 声明 peerDep `^0.80.0`，但 `loader.ts` 的 alias/virtualModules 已把 `@earendil-works/pi-coding-agent`/`pi-tui` 重定向到 GitPilot 0.81.1 宿主，且 `getNpmInstallArgs` 用 `--legacy-peer-deps`/`--omit=peer` 跳过 peer 求解。**版本不匹配不构成阻断**。
- P0 spike 必须验证：rtk-optimizer 未调用 0.81.1 之外的新增 API（若有则锁定 0.8.3 回退）。

### D3. 配置目录桥接到 ~/.gitpilot/agent
- `main.ts` 启动早期注入 `process.env.PI_CODING_AGENT_DIR = getAgentDir()`，使 pi-rtk-optimizer 配置写到 `~/.gitpilot/agent/extensions/rtk-optimizer/config.json`，与 v1 §5.3 统一目录要求一致。
- 不读取、不迁移用户原有 `~/.pi/agent` 数据。

### D4. rtk 二进制不随 GitPilot 分发
- 默认 `guardWhenRtkMissing=true`：rtk 二进制可用时命令重写生效，不可用时降级为原始命令。
- 输出压缩（纯文本管道）作为主能力，**完全离线可用**，符合 v1"不依赖用户机 npm/公网"要求。
- rtk 二进制打包留作未来可选增强（需单独供应链审查），本次不做。

### D5. 两层 rtk 开关（用户重点）
1. **扩展级开关**：`settings.json` 的 `bundledExtensions.rtk-optimizer`（boolean），禁用整个扩展，受 `--no-extensions` 控制。
2. **功能级开关**：pi-rtk-optimizer 自身配置文件（`enabled`/`mode`/`outputCompaction.enabled` 等），通过 `/rtk` 命令或 Desktop GUI 修改。
3. **Desktop GUI 开关**：`TargetUserMenu` 加 rtk 总开关项（映射 bundledExtensions）；`/rtk` 命令打开原生设置 Dialog（mode/压缩细粒度开关）。

### D6. /rtk 命令 Desktop 适配
- `/rtk`（设置模态框，TUI custom）→ `hostAction: "open_rtk_settings"`，`uiCapability: "tui-custom"`，Desktop 用原生 `RtkSettingsDialog` 适配（不调 `ctx.ui.custom()`）。
- `/rtk show|path|verify|stats|clear-stats|reset|help`（文本输出）→ `uiCapability: "rpc-standard"`，走 notify/setWidget/set_editor_text。
- 手工输入 `/rtk ...` 发送也经同一 hostAction 路由（v1 §6.1 要求）。

### D7. postinstall 处理
- 内置精选构建期打入 sidecar，不在 `/.pi/agent/extensions/` 路径，0.9.0 postinstall 不触发。
- overrides 已含 `protobufjs`/`ws`，与 rtk-optimizer 0.9.0 一致；构建流程评估是否需手动应用 `patch-vulnerable-deps.mjs`（P0 验证）。

## 六、实施分期

- **P0 兼容性 spike**：Node CLI 临时加载 `pi-rtk-optimizer@0.9.0`，验证命令注册、事件钩子、alias 重定向、0.81.1 宿主兼容；记录压缩 token 增量与 rtk 缺失降级行为。未通过则锁定 0.8.3 回退。
- **P1 CLI 内置能力**：curated manifest、精确依赖、分级加载、bundledExtensions、重复安装保护、PI_CODING_AGENT_DIR 桥接；验证原生 `/rtk` 全部子命令。
- **P2 RPC 与 Desktop 标准能力**：RpcSlashCommand hostAction/uiCapability、/rtk 子命令 RPC、补齐 setStatus/setWidget/notify/set_editor_text 事件消费、压缩指标与重写通知可见。
- **P3 Desktop rtk 开关 GUI**：RtkSettingsDialog、TargetUserMenu 总开关、hostAction 路由。
- **P4 治理与发布验收**：rtk-optimizer 进 lockfile/许可清单；离线 MSI/NSIS 真机测试（无 rtk 二进制、无 npm、无公网时输出压缩仍可用）；开关关闭后无重写/压缩；能力可独立禁用。

## 七、验证矩阵（rtk-optimizer 专项）

### CLI
- `get_commands` 含 `/rtk`、`/rtk show` 等子命令，无冲突。
- `/rtk show` 输出当前配置与运行时状态；`/rtk stats` 输出压缩指标；`/rtk reset` 重置配置。
- 命令重写：rtk 可用时 rewrite 生效；rtk 不可用时 `guardWhenRtkMissing=true` 运行原始命令。
- 输出压缩：bash/read/grep 输出经压缩管道，token 占用下降可观测。
- `bundledExtensions.rtk-optimizer=false` 时扩展不加载，无重写/压缩。
- `pi install npm:pi-rtk-optimizer` 提示"已由当前 GitPilot 版本内置"，不重复安装。

### RPC/Desktop
- `/rtk` 点击与手工输入均打开原生 RtkSettingsDialog，不调 `ctx.ui.custom()`。
- rtk 总开关在 TargetUserMenu 可切换并持久化。
- 重写通知（notify）与压缩指标（setWidget）不再静默丢失。
- `set_editor_text` 正确预填输入框。
- 断网、无系统 Node/npm 的已安装 Desktop 仍能列出并执行 /rtk 子命令与输出压缩。

### 构建与安装
- `gitpilot-cli` 定向测试与 build 通过。
- `gitpilot-desktop` Vitest、build、sidecar build 通过。
- `python scripts/check_encoding.py` 与 `git diff --check` 通过。

## 八、风险与回退

| 风险 | 应对 |
| --- | --- |
| 0.9.0 与 0.81.1 宿主 API 不兼容 | P0 spike 验证；不兼容则锁定 `0.8.3`（最后稳定版，peerDep 仍含 ^0.80.0） |
| postinstall 补丁未生效致依赖漏洞 | 构建期手动应用 `patch-vulnerable-deps.mjs` 或在 overrides 显式锁定 |
| rtk-optimizer 配置仍落到 ~/.pi/agent | P1 验证 `PI_CODING_AGENT_DIR` 桥接生效；扩展内若硬编码 ~/.pi 则提 issue 跟踪 |
| 内置 + 用户旧版 npm 安装双份冲突 | 重复安装保护拦截 + detectExtensionConflicts 兜底报冲突 |
| 任一 P0 未闭环 | rtk-optimizer 标记为实验能力，`defaultEnabled=false`，不默认向所有 Desktop 用户开放 |

## 九、不改动的边界
- 不修改 backend、pi-runtime 或平台 AgentRuntime 工具契约（与 v1 §15 一致）。
- 不 fork pi-rtk-optimizer 上游包，只维护轻量 wrapper、能力清单与 Desktop adapter。
- 不升级 Pi Core（0.81.1）；若证明需升级另立变更。
