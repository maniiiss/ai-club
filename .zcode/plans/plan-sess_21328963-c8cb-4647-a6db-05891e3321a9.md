# GitPilot 按需下发工具实现方案

## 背景与根因（已确认）
GitPilot 项目助手走 Pi runtime（Ark `deepseek-v4-flash`）。backend 在 `RuntimeToolContractService.build()` 把 24 个 MCP 工具全量下发（普通会话 `restrictedToolCodes=null`），超过该模型有效阈值，导致 thinking 在第一个词就 `THINKING_END`、不产出正文，pi-runtime 仍上报 `RUN_COMPLETED(SUCCESS)`，用户看到空回复。实验铁证：0/12 个工具正常，24 个异常。

## 目标
根据用户本轮输入（question + slashCommand + route）动态选出相关工具子集下发，控制在阈值（≤12）内；规则匹配为主，向量检索兜底，未命中下发核心工具集。覆盖 assistant 抽屉（Pi runtime）+ 聊天室。

## 架构设计

### 新增组件
1. **`PlatformToolSelector`**（新服务，`service/PlatformToolSelector.java`）：按需选工具的唯一入口。
   - 方法：`Set<String> select(ToolSelectionContext ctx)`
   - `ToolSelectionContext`：question、slashCommand、routeName、projectId、candidateToolCodes（候选集=全量或房间启用）、currentUser
   - 流程：① slashCommand 精确映射 → ② 关键词匹配（复用 Orchestrator 词表 + `containsAny`）→ ③ 规则未命中时向量检索 top-N → ④ 与候选集取交集 → ⑤ 上限裁剪 ≤12 → ⑥ 全空则核心工具集
2. **`PlatformToolSemanticIndex`**（新服务，`service/PlatformToolSemanticIndex.java`）：向量索引与检索，仿 `WikiKnowledgeSearchService`。
   - 启动时把 24 个工具的 enriched 描述（基础描述 + keywords + 示例问题，代码常量维护在 `PlatformToolRegistry` 或本类）upsert 到 Qdrant collection `platform_tools`
   - `search(question, topK)`：embedding → Qdrant search → 返回 toolCode 列表
   - embedding 模型复用 Wiki 的 `ModelConfigService.generateEmbedding`；未配置 embedding 时 `vectorFallbackEnabled=false` 自动降级为纯规则
3. **`PlatformToolSelectionProperties`**（配置，`config/PlatformToolSelectionProperties.java`）：
   - `enabled`（默认 true）、`maxTools`（默认 12）、`vectorFallbackEnabled`（默认 true，embedding 未配时自动 false）、`coreFallbackToolCodes`（核心集，默认 8 个高频只读工具）

### 规则表（代码常量维护）
- **slashCommand → 工具子集**：`/需求`→work_item.*+project.get_detail；`/wiki`→wiki_space.*+wiki_page.*+document.convert_markdown；`/执行任务`→execution_task.*+work_item.get_detail；`/仓库扫描`→repo_scan.*+gitlab_binding.search；`/测试`→test_plan.*；`/迭代`→project.list_iterations+project.get_iteration_detail+work_item.search；`/文件库`→document.convert_markdown+wiki_space.search
- **关键词 → 工具子集**（复用 `AssistantToolOrchestrator` 的 `isCollectionIntentQuestion`/`isRequirementCreationIntent` 等词表与 `AbstractAssistantPromptSkill.containsAny`）：项目→project.*；需求/任务/缺陷→work_item.*；迭代/发版→project.list_iterations+get_iteration_detail；成员/负责人→user.*；Wiki/知识/文档→wiki_*+document.convert_markdown；测试/用例→test_plan.*；执行/运行→execution_task.*；仓库/GitLab/扫描→gitlab_binding.*+repo_scan.*；Agent/智能体→agent.*

### 核心工具集（未命中 fallback，≤8）
project.search、project.get_detail、work_item.search、work_item.get_detail、agent.list_available、wiki_space.search、user.list_project_members、document.convert_markdown

## 接入点改动（复用 restrictedToolCodes 通道）

### 1. assistant 抽屉（Pi runtime）
`AssistantChatService.executeChat`（line 435-472）Pi 分支：
- 在调 `withToolContract` 前，用 `PlatformToolSelector.select(ctx)` 算出 `selectedToolCodes`
- 把 `withToolContract(..., null, null, externalTools)` 改为 `withToolContract(..., selectedToolCodes, null, externalTools)`
- `selectedToolCodes` 与 external MCP 工具不冲突（external 走 `external_mcp__` 前缀，build 里独立 append）
- 注意：selectedToolCodes 只作用于平台工具，外部 MCP 工具仍按会话快照下发（但若外部工具多也超阈，后续可再优化）

### 2. 聊天室
`ChatAssistantService`（line 587-593 现传 `toolExecutionPolicy.enabledToolCodes()`）：
- selector 的 `candidateToolCodes` = 房间启用的工具集（房间策略优先）
- `selectedToolCodes = selector.select(ctx with candidateToolCodes=房间启用集)`
- 即"按需选 ⊂ 房间启用"，selector 在房间启用集内按需筛选
- 传 `withToolContract(..., selectedToolCodes, autoExecuteCodes, externalTools)`

### 契约保证（无需改 pi-runtime）
`build()` 的 `allowedCodes = definitions.map(toolCode)`（line 85）自动同步下发的 tools 与 `toolPolicy.allowedToolCodes`，pi-runtime `beforeToolCall` 白名单预检不会误 block。

## 配置
`application.yml` 新增：
```yaml
platform:
  assistant:
    tool-selection:
      enabled: ${PLATFORM_TOOL_SELECTION_ENABLED:true}
      max-tools: ${PLATFORM_TOOL_SELECTION_MAX_TOOLS:12}
      vector-fallback-enabled: ${PLATFORM_TOOL_SELECTION_VECTOR_FALLBACK:true}
```

## 风险与回滚
- **召回不全**：规则+向量双路 + 核心集 fallback 兜底；`enabled=false` 一键回退全量下发
- **向量延迟**：每轮 ~100-300ms embedding；`vectorFallbackEnabled=false` 可关
- **embedding 未配**：自动降级纯规则，不报错
- **GitNexus impact**：实现前对 `AssistantChatService.executeChat`、`ChatAssistantService`、`RuntimeToolContractService.build` 做 upstream impact 分析，确认 d=1 调用方都更新

## 实现顺序
1. `PlatformToolSelectionProperties` + 配置
2. `PlatformToolSemanticIndex`（向量索引/检索 + 降级）
3. `PlatformToolSelector`（规则表 + 调用向量 + fallback + 裁剪）+ 单测
4. 接入 `AssistantChatService` Pi 分支 + 接入 `ChatAssistantService`（候选集=房间启用）
5. 真实 pi-runtime 复现验证（24→≤12 恢复 TEXT_DELTA）
6. 文档更新
7. GitNexus impact + 编码检查 + Maven 测试
