# GitPilot-desktop 附件上传与解析工具 — 实施方案

## 决策结论（基于已确认的范围）
- **形态**：① 输入框附件上传 UI（选择器 + 拖拽 + 粘贴图片）；② 同时向 pi-agent-core 注册一个**模型可调用**的 `parse_attachment` 工具。
- **解析位置**：本地 sidecar（`gitpilot-cli`），离线零网络，契合安全边界（渲染层无 fs 权限，所有读取/解析在 sidecar）。
- **格式**：图片（png/jpg/gif/webp/bmp，复用现成 `image-process`）+ 文档 pdf/docx/xlsx/pptx（新增 TS 库）。
- **核心复用**：协议层 `prompt/steer/follow_up` 的 `images?: ImageContent[]` 字段两端已定义且 sidecar 已透传给 agent（`rpc-mode.ts:401`）——图片上传**无需改协议**，只填 UI。文档则把抽取文本以 `<file name="...">…</file>` 块追加到 message（与 CLI `@file` 一致，agent 已识别）。

## 架构与数据流

```
[渲染层 InputBox]  ──pick/drag/paste──▶  rpc.prepare_attachments(items)
        │                                      │ (paths 或 inline base64)
        │                                      ▼
        │                              [sidecar] prepareAttachment() 共享核心
        │                                      ├─ 图片: mime.ts + image-process.ts (photon-node)
        │                                      └─ 文档: document-parser.ts (mammoth/unpdf/xlsx/jszip)
        │                                      ▼
        ◀──── PreparedAttachment[] ────────────
        │
   附件 chips（图片缩略图/文档 chip）+ remove
        │ on send
        ▼
   rpc.prompt(promptMessage, images)
        ├─ images: 图片 ImageContent[]  → 走已有 images 字段
        └─ promptMessage: 用户文本 + 文档 <file> 块  → 走已有 message 字段

[模型] 亦可主动调用 parse_attachment(path) 工具 → 同一 prepareAttachment() 核心 → AgentToolResult(text+image)
```

要点：**解析逻辑只写一份**（`prepareAttachment`），被 ① 上传 RPC、② agent 工具、③（可选）重构后的 CLI `file-processor` 三处复用。

## 第一部分：gitpilot-cli（sidecar）

### 1. 新增依赖（`gitpilot-cli/package.json`）
- `mammoth`（docx → html/text，纯 JS，bun 友好）
- `unpdf`（pdf 文本抽取，现代 ESM，bun 友好；比 pdfjs-dist 轻）
- `xlsx`（SheetJS 社区版，xlsx → 文本/CSV）
- `jszip`（pptx = OOXML zip，读取 `ppt/slides/slideN.xml` 抽 `<a:t>` 文本节点；v1 仅文本，不抽图片/图表）

### 2. 新增 `src/utils/document-parser.ts`
- `extractDocumentText(buffer: Buffer, ext: string): Promise<{ text; truncated; warnings }>`
- 按扩展名分发：pdf→unpdf、docx→mammoth、xlsx→xlsx、pptx→jszip+XML 文本抽取
- 统一处理：单文件最大 20MB（对齐后端 `platform.upload.max-document-size`），抽取文本上限 15000 字符（对齐后端 `HERMES_ATTACHMENT` maxChars），超限置 `truncated=true` 并附 `warnings`。

### 3. 新增 `src/core/attachments/prepare-attachment.ts`（共享核心）
- 类型：
  ```ts
  type AttachmentInput = { path: string; name?: string } | { name: string; data: string /*base64*/; mimeType?: string };
  interface PreparedAttachment {
    name: string; path?: string;
    kind: 'image' | 'document' | 'text';
    mimeType: string; sizeBytes: number;
    text?: string;              // document/text 抽取结果
    image?: ImageContent;       // 图片（pi-ai ImageContent，base64）
    truncated?: boolean; warnings?: string[];
  }
  ```
- `prepareAttachment(input, opts): Promise<PreparedAttachment>`：
  - 图片：`detectSupportedImageMimeType`（buffer 嗅探）→ `processImage`（photon-node 压缩）→ `ImageContent`
  - 文档（pdf/docx/xlsx/pptx）：`extractDocumentText`
  - 其它（txt/md/json/csv/源码）：utf-8 读取 + `truncateHead`（复用 `truncate.ts`）
  - 错误收敛为 `warnings`，不抛 `process.exit`（CLI 版的旧问题在此修正）

### 4. 新增 `src/core/tools/parse-attachment.ts`（agent 工具）
- 镜像 `read.ts`/`ls.ts` 模式：`createParseAttachmentToolDefinition(cwd)` 返回 `ToolDefinition`，name=`parse_attachment`，只读，params `{ path: string; maxChars?: number }`。
- `execute` 调 `prepareAttachment({path})`，返回 `AgentToolResult`：`content = [{type:'text', text}, ...(image? [{type:'image',...}])]`，出错 throw（遵循 pi 约定）。
- 提供 `renderCall`/`renderResult`（TUI，参考 read.ts）。

### 5. 接入工具注册表（`src/core/tools/index.ts`）
- `ToolName` 联合 + `allToolNames` 集合加 `"parse_attachment"`；
- `ToolsOptions` 加 `parseAttachment?`；`createToolDefinition`/`createTool`/`createAllToolDefinitions`/`createAllTools` 各加 case/字段。

### 6. 默认启用（`src/core/agent-session.ts`）
- `_buildRuntime`（~2569）`createAllToolDefinitions` 传 `parseAttachment`；
- `defaultActiveToolNames`（~2601）加 `"parse_attachment"`（只读、低风险，作为 `read` 的天然伙伴默认开启）。*此点会改变 CLI/SDK/桌面三端默认工具集——见末尾「风险与可回退」。*

### 7. 新增 RPC 命令 `prepare_attachments`
- `gitpilot-cli/src/modes/rpc/rpc-types.ts`：加 command
  `{ type: 'prepare_attachments'; items: AttachmentInput[] }` + response
  `{ command: 'prepare_attachments'; success: true; data: { attachments: PreparedAttachment[] } }`，导出 `PreparedAttachment`/`AttachmentInput`。
- `gitpilot-cli/src/modes/rpc/rpc-mode.ts`：`handleCommand` 加 `case "prepare_attachments"`，对每个 item 调 `prepareAttachment`（path 经 `resolveReadPath` 解析，inline 解 base64），聚合并发执行。

### 8. （可选/二期）重构 `src/cli/file-processor.ts`
- `processFileArguments` 改为内部委托 `prepareAttachment`，保留 CLI `process.exit` 语义。消除三处解析逻辑重复。**不影响桌面/RPC 路径，可独立提交。**

### 9. 文档
- 更新 `gitpilot-cli/docs/rpc.md`：在 `### Commands` 下新增 `### Attachments` 小节，描述 `prepare_attachments` 请求/响应。
- 更新工具说明（`parse_attachment` 的 description 已含于工具定义）。

## 第二部分：gitpilot-desktop（渲染层）

### 10. 协议类型（`src/rpc/types.ts`）
- 加 `PreparedAttachment`、`AttachmentInput`，`RpcCommand` 加 `prepare_attachments`，`RpcResponse` 加对应成功分支。

### 11. 桥接（`src/rpc/bridge.ts`）
- 加 `rpc.prepareAttachments(items)`；
- 扩展 `rpc.prompt(message, images?)` / `rpc.steer(message, images?)` / `rpc.followUp(message, images?)` 透传 `images`（类型已支持，仅补参数）；
- `mockResponseFor` 加 `prepare_attachments` 分支，浏览器预览可用。

### 12. 会话 store（`src/store/session.ts`）
- `UIMessage` 加 `attachments?: UIAttachment[]`，`UIAttachment = { name; kind; mimeType; sizeBytes; previewUrl? }`（**仅元数据**，不存文档原文，避免 UI 臃肿）；
- `prompt(message, attachments?)` / `steer(message, attachments?)`：
  - `promptMessage = message + docs.map(a => '\n<file name="'+a.name+'">\n'+a.text+'\n</file>').join('')`
  - `images = imgs.map(a => a.image)`
  - `await rpc.prompt(promptMessage, images)`
  - 推入 UIMessage：`text=message`（用户原话），`attachments=元数据`（图片带 previewUrl=base64 data URL，文档带 name/size）。

### 13. 输入框（`src/components/InputBox.tsx`）
- 附件按钮（`Paperclip` 图标）→ `@tauri-apps/plugin-dialog` `open({ multiple:true, directory:false })` → paths → `prepareAttachments`；
- 拖拽：Tauri 2 `getCurrentWebview().onDragDropEvent`（`drop` 给 `paths`，webview 下 HTML5 drop 不给路径）→ `prepareAttachments`；
- 粘贴：HTML5 `onPaste` → 剪贴板图片 blob → `FileReader` base64 → `prepareAttachments({name,data,mimeType})`；
- 本地 `attachments` state：chip 列表（图标+名+大小+× 移除），解析中显示 spinner，失败显示错误 chip；
- 发送：解析中禁用 send；发送后清空 attachments；Enter/Shift+Enter 行为不变。

### 14. 消息渲染（`src/components/MessageBubble.tsx`）
- user 消息：若 `message.attachments?.length`，在文本上方渲染缩略图行（图片 `<img>` 缩略图 + 文档 chip）。

### 15. 样式（`src/index.css`，紧邻现有 `.input-composer*` 规则）
- `.input-composer__attachments`、`.attachment-chip`、`.attachment-chip--loading`、`.attachment-thumb`、消息内 `.chat-message__attachments`。

### 16. 设计文档
- 新增 `docs/design-docs/gitpilot-desktop-attachments-technical-design-v1.md`（AGENTS.md 要求：跨模块 + 协议扩展 + 新工具必须落设计文档）。

## 验证（Harness，按 AGENTS.md 优先级）
1. `python scripts/check_encoding.py`（UTF-8 无 BOM / 中文未转义）
2. `cd gitpilot-cli && npm run build && npm test`（tsc 类型 + vitest）
3. `cd gitpilot-desktop && npm run build`（前端类型 + 构建）
4. 重建 sidecar：`gitpilot-desktop/sidecar/build.sh`，冒烟：选图片+pdf→发送→确认图片到达模型、文档 `<file>` 文本注入；对话中触发 `parse_attachment` 工具。

## 风险与可回退
- **默认启用 parse_attachment 工具**：会让 CLI/SDK/桌面三端默认多一个只读工具。若希望保守，可改为「注册但不默认 active」（与 grep/find/ls 一致按需激活），仅改一行（不加 `defaultActiveToolNames`）。我会默认开启，如你倾向按需可告知。
- **bun --compile 打包新依赖**：mammoth/unpdf/xlsx/jszip 均纯 JS（无原生/WASM，unpdf 默认无 WASM），应可随 `bun --compile` 打包（photon-node WASM 已有先例）。构建步骤会验证；若某库打包异常，回退为该格式走后端转换（第二选项已在决策中备好）。
- **pptx 抽取质量**：v1 仅文本（jszip+XML），不含嵌入图片/图表；后续如需可再评估。
